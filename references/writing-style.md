# 话术风格：面向业务与人才发展的管理解读

## 一句话定义

**用适合管理汇报、主管和本人都能听懂的语言，先概括日常做事特点或主要关注，再解释在任务中的可能表现、对判断/推进/交付/协作的影响，最后用少量数据支持。个人看HPI组合，群体兼顾共性和差异。**

不是写心理学术语翻译，不是包装性人才标签，也不是把分数逐项念一遍。立体不等于文绉绉，更不等于编复杂故事。


## 新增校准：通俗不等于随意，专业不等于抽象

分支要求是**管理解读**，不是把报告改成聊天口吻。可以使用“判断依据、优先级、关键节点、交付完整性、协作方式、反馈接纳”等清楚的工作语言；不能只写术语、不交代它在工作里具体指什么。

正文避免“嘴快、抢戏、死磕、乖、带头大哥、光说不干”等随意或贬损标签。问句可用于观察清单，但结论页应以完整陈述句为主，不整页都写“会不会、能不能”。

| 表达层次 | 示例（条件性写法，不指向真实人员） | 判断 |
|---|---|---|
| 只复述分数 | 审慎高，好奇高。 | 没有解释一起出现时怎样做事 |
| 只有抽象提醒 | 提升灵活性，强化成果转化。 | 看不出要改什么以及影响谁 |
| 太口语、像评人 | 想得多、死磕细节，交东西慢。 | 定性重，缺情境和证据，不适合汇报 |
| 管理解读 | 重步骤和质量标准；需求改变时，需观察能否及时调整任务范围，避免继续打磨不再需要的内容，影响交付时间。 | 有特点、情境、行为、影响和观察方向 |

“专业”来自证据、恰当判断和对工作过程的理解，不是词汇更难；“立体”来自特点组合与条件差异，不是写得更长。

## 页面表达：标题给判断，正文说明怎么影响工作

默认顺序为：

**结论标题 → 可能的工作表现及影响 → 1–2项关键数据。**

需要发展建议时，在此基础上补**与该行为一一对应的支持方式**，不要只列“培训、辅导、复盘”。不要求所有要素挤成一个超长句。

示例：

> **计划性不同，交付支持需要区分。** 资料显示有人更重步骤和标准，有人更偏边做边调整；前者需观察需求变更时能否及时取舍，后者需关注过程检查和收尾，分别避免反复修改或临近交付补漏。依据放该批次实际分布，不能编人数。

标题本身也不能比证据更强：正文说“有学习兴趣”，标题不能改成“学习能力强、潜力突出”。

## 优势也要解释工作价值，不能只有风险写业务

在报告证据支持时，应同时说清：这种倾向可能帮助哪一步工作，什么条件下有价值，成效要用什么实际结果看。不能把有利倾向直接说成已具备业务能力。

| 倾向线索 | 管理解读写法示例 | 仍要验证什么 |
|---|---|---|
| 愿意学习探索 | 面对陌生任务，倾向主动补充知识、寻找方法，有助于理解问题和提出方案。 | 方案是否回应关键问题、是否完成任务 |
| 主动承担与交流 | 愿意接触相关同事、表达观点，有利于发起讨论和推动分工。 | 是否听清需求、确认责任、持续跟进 |
| 重计划和质量 | 倾向先明确要求与步骤，可为排期、检查和质量控制提供支持。 | 需求变化时是否调整，交付是否及时完整 |
| 重专业依据 | 任务沟通中讲清判断依据和方案取舍，可能更有助于其投入讨论。 | 是否真正采纳信息；不能认定分析能力更强 |

以上是编辑示范，并非自动结论库。对应倾向缺少证据时，不得套用。


## 五条必须做到

1. **先说人，再说分。** “愿意承担和推动，沟通方式较温和”比“高抱负×高人际敏感度”更适合正文；后者放依据。
2. **写能看见的动作。** 写“承诺交付前，尚未核实人手和排期”，不要只写“承诺边界不足”。
3. **写工作后果。** “合作方太晚知道延期风险，来不及改排期”比“协同受影响”更明确。
4. **把几个倾向组合起来。** 不只写“爱学、爱说、认真”；要说明这些特点一起出现时，其做事方式是什么。
5. **不把假设当事实。** 根据报告只写可能、倾向和观察；有真实工作记录才写“出现过”，且区分来源。

## 个人核心画像：主要基于HPI

顺序是：选2–3个最有解释力的HPI单点 → 看相互强化或不同侧面 → 写成一个人的工作方式。

可考虑但不强求全部写入：是否主动接任务/争取带头，如何准备/安排/调整，如何学习新东西，怎样说话/听人说话/处理分歧。其他维度不突出，就不硬贴标签。

HDS主要解释特定压力状态；MVPI解释投入来源。不能再固定用一条HPI、一条MVPI凑“核心画像”。用户只要求HPI画像时，不擅自混入HDS/MVPI。

**组合写法示范，均为条件性例子，不指向真实受测者：**

| HPI组合，须先核对当批报告含义 | 可采用的立体表达 | 不应推断 |
|---|---|---|
| 抱负较高 + 人际敏感度较高 | 愿意承担和推动，但更习惯商量，不愿把关系弄僵。 | 已有领导能力；只会讨好 |
| 好奇较高 + 审慎较高 | 愿意找新办法，也希望先把步骤和要求安排清楚。 | 必然完美主义；一定能按时落地 |
| 抱负/好奇较高 + 审慎较低 | 喜欢发起新尝试，更偏边做边改；具体排期和收尾要另看。 | 执行力差；不负责任 |
| 社交较高 + 人际敏感度偏低 | 愿意交流、敢讲意见，表达更直接。 | 不尊重人；缺乏同理心 |
| 学习方式较高 + 抱负中等 | 愿意认真学、准备充分，但不一定抢着做负责人。 | 没有事业心；能力不足 |

这些组合不是官方预测公式，也不是自动打分标签。实际维度解释以授权报告为准；中间分不能硬拆成高/低两极。

## 需关注：必须从行为写到后果

写作骨架：

**在什么场景 → 可能怎么做 → 对哪件工作/谁造成什么影响 → 具体观察什么。**

不要求四段都单独成句，但读者必须能回答四个问题。例：

> 需求已经改变时，仍可能按原标准继续打磨，做出不再需要的内容，增加返工；重点看能否及时调整任务范围和交付标准。

> 讨论新方案时可能先讲自己的做法，没有听清合作方的人手与排期限制，导致定下的安排难以执行；定方案前要看各方能否说明“谁做、何时交、哪里有困难”。

> 接受新任务时可能先答应日期，之后才发现人手不够，影响按时交付；重点看承诺前是否核对工作量、资源和依赖条件。

这些例子只适用于有报告证据支持的观察假设，不能作为人人相同的万能风险。

## 群体报告：讲共性，也讲例外

每条重要结论使用“群体倾向 → 工作中的可能做法 → 有益影响或代价 → 关注重点”。数据只保留1–2个关键支撑，完整分布放图和备注。不要把均值套到每个人；人数、范围、不同组合与例外要有依据。

不写：“这批人都是创新型人才，后端闭环不足。”
改为：“多数愿意提出新办法，但做事安排差异较大。有人会先列计划，有人更习惯边做边改；需要分别看谁容易反复修改、谁容易漏掉后续跟进。”

如果只有均值，不能写“多数”“全员”“两极分化”。如无实际人数/分布，改成“该批次均值呈现……，还需查看个体分布”。

## 两批对比：分别给关注点，不制造对立

结构：共同点 → 主要差异 → A批在什么任务里重点看什么 → B批更需看什么。每个关注点要带工作后果，不能一边只写性格、一边只写培训动作。

差异小就写“接近”；相同均值不能写出相反结论。不同关注点不代表互斥，也不把成熟度、资历或培养效果直接归因于届别。

## 禁止用这些词替代具体含义

| 不采用的写法 | 应当写清的意思（示例） |
|---|---|
| 把想法接上闭环 | 提出方案后，明确谁负责、何时交，并持续跟进到完成。 |
| 沉着不等于反馈充分 | 遇到困难时会不会及时说，让合作方有时间补人手、改排期。不能仅凭调适分数断定少沟通。 |
| 提升灵活性 | 需求改变后，能否调整优先级、任务范围或原有做法。 |
| 前端发散、后端收敛不足 | 新方向越研究越多，原本最重要的问题反而迟迟没回答。 |
| 强化业务链接 | 写出实际任务、合作对象和工作后果；“业务链接”不是正文结论。 |
| 拉通协同、赋能结果转化 | 说明各方负责什么、哪里需要配合、是否按时交到下一位同事手里。 |
| 校准自信、接纳反证 | 别人拿出相反事实时，是否愿意重新检查判断并修改方案。 |
| 提升交付意识 | 分清哪些必须本次完成、哪些可后续完善，按约定时间交出能用的版本。 |

## 不能用直白当借口贴标签

- 不写“固执、不靠谱、冷漠、狡猾、没事业心”等作为人的定性。HDS“狡猾”若是原量表名，可在图表保留，解释不能变成品行判断。
- 传统低：描述对等级、惯例或权威的偏好，不直接推断绕流程、违法或不守规则；规则执行还要结合日常做法、具体情境和实际记录。
- 高学习方式不是学习能力强，高科学不是分析能力强，高商业不是会做生意。
- 没有低分就不硬凑短板；高分也不自动算优势。

## 正文与依据分工

个人PPT核心画像以2句为主，建议约50–90个汉字；“需关注”约2句、每句一个主要场景与后果。三栏小结通常每项1–2句。群体页每项先用一条完整结论，随后1–2句解释。字数是排版目标，不得为了凑字截断含义。

完整HPI组合、原报告解释、常模、页码和统计留在受限备注或证据文件；正文用少量关键分值。不能把所有数据丢到备注就不在正文留下依据，也不能把备注当保密隔离层。

## 成稿前逐条问

“读者能知道他会怎么做吗？”“知道对进度、交付或合作哪一步有影响吗？”“能具体观察吗？”“哪些是来源、哪些是我的推断？”“换另一个人的名字，这段还能原样用吗？”

前三问答不出来，就重写；第五问经常答能，说明写得太空泛。保留来源能支持的差异，不为了去重而编造人格特征。


## 发展建议必须接住前面的分析

群体总结保留三栏：**可放大的优势／需管理的风险／对应的发展建议**。底部再用“正向价值／需要防范”说明对业务与组织的影响。三栏可以主题对应，不要求每个优势都强行配一项风险。

建议要说清解决哪一类工作问题：

- 反复打磨可能拖慢关键交付：明确本次必须完成与后续优化的范围，练习取舍；不能只写“提升效率”。
- 少跟进可能造成漏项：约定负责人、检查点和验收清单；不能一律要求增加标准、更多复盘。
- 被质疑时可能先解释立场：要求核实不同意见的事实依据，说明采纳或不采纳的理由；不是压低主动性。
- 需求未听清可能反复确认：先复述需求、合作约束和下一步分工；不是笼统“提升沟通能力”。

建议以资料支持的问题为前提；用户只要画像或结论时，不擅自扩成培训方案。

## 人群与个体的不同写法

个人核心画像先讲其HPI组合的日常做事方式；需关注另讲条件和影响，不让“画像”全变风险清单。三表结论不能互相替代。

群体页先讲共性，再用有依据的明显差异补充例外。差异个体不仅看低分，也要考虑高于群体的做事方式；不按能力排优劣、不为了凑人数列人。授权展示的个体卡用“显示名｜不同在哪里；可能工作表现与影响；个人值/群体值及相关组合依据”。

跨批比较优先解释主要差异，分别写两批在工作中需关注什么；共性保留，区别不互斥。不要把微小分差扩成两种完全相反的人群。

## 人工审稿的六个必答问题

1. 标题有没有先说清主要判断，且没有把倾向夸成能力？
2. 正文有没有一个具体动作，而非只把量表词改写成形容词？
3. 优势有没有说出工作价值，风险有没有说出合理的一步后果？
4. 观察或建议是否能直接对应前面的行为？
5. 有多少来源、多少计算、多少推断，读者能否区分？
6. 群体与差异个体是否互相补充，没有把某一个人的特点说成全体？

可用`narrative_check.py`检查结构缺项，用`style_check.py`提示部分不合适表达。自动检查通过不等于语义、业务解释或测评解读正确。
