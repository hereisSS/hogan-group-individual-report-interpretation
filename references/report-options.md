# 报告结构、身份显示与热力图选项

这些是v2.1的运行配置，不是所有项目必须遵循的固定页码。按用户最新、明确的要求记录；已确认的信息不反复询问。参考图缺失或读取不全时，说明能沿用什么，不声称已精准复现。

## 任务和结构

- `task_mode`：`personal` / `group` / `both` / `comparison`。
- `group_profile`：`management12`（完整管理解读，默认群体结构）；`compact10`（兼容原10页）；`custom`（用户指定结构，另附outline）。
- `include_development_advice`：默认true，仅结论请求设false；管理解读模板三栏总结中的“建议”按请求替换成“观察重点”，不额外增加培养动作。
- `charts.include_median`：单批群体概览默认true；跨批默认false。缺少中位值及个人原分时不能设true。
- 单批均值/中位值用不同颜色和线型，数值直接放对应点旁；跨批颜色先区分批次，中位值若被要求再用线型区分，不偷换编码。

模板优先级保持不变：本次指定 > 明确可访问历史 > 内置。机器配置`template_choice=user_selected`时需`template_overrides`给出对应`personal`/`group`/`comparison`的实际模板引用，检查器不会擅自替换成内置。

## 名称与受众

`display_names`支持`random_codes`、`aliases`、`full_names`；默认随机代号。姓名不是跨所有任务的固定配置。

启用实名需要同时有：当次或明确延续的实名指令、确认的阅读对象、对该受众的身份展示授权、经用户确认的映射。`authorization.full_name_display_allowed=true`和`identity_mapping_confirmed=true`只是执行记录，不能替代真实权限。缺一时暂停实名成稿，列明缺项；不猜测名字、不悄悄替换成其他人，也不把安全默认当理由忽略已经明确的授权要求。

身份资料以稳定成员ID关联。用户纠正姓名或缩写，只更新获授权运行目录中的映射与受影响标注；已经核对的分数不因改名而重算。只改显示名时不用重新核对所有雷达图数值，但被改标注的图像应重新目检并记录版本。

`show_identity_mapping`默认false；当明确要求在附录展示且受众有权查看时才true。映射不进公共Skill、测试、README或共享日志。编号和缩写版本仍受保密限制。

## 热力图

### 默认保留源报告标签

`heatmap.label_scheme=source_labels`时，采用当批核对后的原报告标签。`source_intervals_confirmed`与`source_reference`记录已读取的实际区间及来源，不把历史阈值套入新版本。

### 采用用户参考图的显示标签

`heatmap.label_scheme=custom_display`时需要：`display_labels_confirmed=true`、`display_reference`、`bands`逐项包含`min/max/source_label/display_label/color`。原始统计区间必须已确认，不得为了视觉更改阈值。源标签和显示标签分别保存；即使数字一样，不同标签也不能被称为源报告原文。

示例（只说明此前采用过的映射，下一批必须再核对来源）：

| 区间 | 原报告标签 | 参考图显示标签 |
|---|---|---|
| 0–39 | 无风险 | 低风险 |
| 40–69 | 低风险 | 中低风险 |
| 70–89 | 中等风险 | 中高风险 |
| 90–100 | 高风险 | 高风险 |

图例或脚注要简短说明标签映射；“低风险”不表示没有任何工作风险。四档色调及整体排版以可访问、经指定的参考为准；空白模板用通用占位色带，不代表已经确认下一批分档。

### 观察对象

完整表保留本批所有人；右侧可以展示共性组合，或在授权范围内展示具体观察对象。不要默认固定为5个人或固定某个维度数；选择标准依据当前分布、工作相关性和用户目的写清。多项较高不等于低潜力、低绩效或应淘汰。无许可时不公开身份，也不通过备注变相曝光。

## 配置检查

`plan_report.py`只核验已填写字段的结构和相互约束，输出应使用的模板/统计量/名称模式。它不读取聊天确认、不核实真实权限、不写报告、不证明可比性，也不推送任何文件。
