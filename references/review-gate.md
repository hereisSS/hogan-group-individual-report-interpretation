# 确认与素材版本

默认流程：输入核验 → 数据核对 → 图表生成 → 等待真实用户确认 → 报告分析和制作 → 渲染检查 → 交付。

只有图表审核是默认暂停点。用户确认后立即继续完成PPT，不人为追加一次文案确认。用户本次明确要求先看文字则服从该顺序。

## 个人图：保留v1哈希脚本

`review_gate.py init`验证完整scores.json，为每人3张`{alias}_{scale}.png`及数据、模板记录SHA-256，生成等待状态。它仍只支持个人3N图流程，不冒充群体报告检查器。

```bash
python scripts/review_gate.py init --data "$RUN/scores.json" --template "$RUN/template.pptx" --charts "$RUN/charts" --out "$RUN/review_manifest.json"
python scripts/review_gate.py approve --manifest "$RUN/review_manifest.json" --confirmation '实际用户原话'
python scripts/review_gate.py check --manifest "$RUN/review_manifest.json"
```

必须看到真实确认才能记录，脚本不能鉴别说话人，执行者不能捏造原话。个人数据、图片、模板变化后旧哈希会阻断；纯分析文字更改不使已确认图表失效。

## 群体图与跨批图：按实际产物记录

由执行AI在受限运行目录记录`group_review_manifest.json`（本包不提供群体自动批准程序）：
- 数据及统计来源文件哈希、批次N、基准和规则。
- 群体模板哈希及该次实际图表列表/哈希，不套用3N数量。
- 当前状态、用户真实确认原话和时间、受影响的页面。

哈希可用运行环境的SHA-256工具计算，工具不可用则明确说明未做哈希检查；不能伪造。数据/规则/图表变更时重新交付受影响部分核对，不把旧确认覆盖到新图。

数据已在个人流程核对、用户已确认的原图可复用；新群体图仍需目检，但不要求用户重新上传全部资料。用户明确允许直接成稿时记录其指令，并在交付中说明采用了哪些已确认来源。

## 确认语义

“OK”“雷达图没问题”“确认，继续生成PPT”针对当前素材时就是有效确认，不重复询问。如果同一句提出修改，先处理修改再确认受影响内容。重新设计图表视觉和改变数据一样，不能假装已获旧确认。

## 边界

哈希是版本核对，不是访问控制、加密或防篡改授权系统，也不验证图表数据或文字含义。清单、确认记录和源文件路径均为运行时受保护信息，不提交GitHub。
