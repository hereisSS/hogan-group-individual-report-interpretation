# 交付质量清单

## 授权和保密
- [ ] 已确认本次处理目的、组织认可环境、输入权限和阅读对象。
- [ ] 没有向未获许可的插件、OCR、转码服务、API、网盘或GitHub发送真实资料。
- [ ] 按本次确认的名称模式展示；映射另存，未获身份授权的版本不含姓名对照，任何版本不附无关测试账号。
- [ ] 真实运行文件在仓库外；公开包只含空白模板、方法和虚构样例。
- [ ] 不承诺平台绝不留存，不用“藏在备注”代替权限保护。

## 数据与来源
- [ ] N、批次、成员身份、常模与版本核对一致。
- [ ] 全三表时每人28项，缺项不填0；单表任务不伪造完整数据。
- [ ] 来源定义、总览/摘要/详页已实际查看；核验状态与实际一致。
- [ ] 分档、团队公式、子量表计数规则有确认来源，不静默沿用历史。
- [ ] 均值/中位值/人数同一口径；不从均值反推中位值或个人分布。
- [ ] 旧汇总与原分冲突已披露，跨批比较未偷换来源。

## 图表与确认
- [ ] 维度顺序、0–100刻度、分值、人数、图例一致。
- [ ] 个人图每人3张；群体图按实际需要；原图确认后不重绘。
- [ ] 中文无缺字、标签无重叠、边界不裁切，全部图像目检。
- [ ] 真正收到用户对当前版本的确认；没有自行编造确认。
- [ ] 变更素材后核对受影响部分，不反复确认未变化内容。

## 文字与工作影响
- [ ] 个人核心画像主要以HPI单点与HPI内部组合形成，而非固定塞入MVPI。
- [ ] 写出主动性、做事安排、合作等最有区别的部分，不只列形容词。
- [ ] 每条关键关注有具体场景、可能行为、工作后果和观察重点。
- [ ] 没有“把想法接上闭环”“沉着不等于反馈充分”等代替具体意思的句子。
- [ ] 群体共性有分布/人数依据，例外和内部差异没有被均值盖住。
- [ ] 跨批分别说明关注什么；差异小写接近，不硬分两类人。
- [ ] HPI不是能力，HDS不是已发生问题，MVPI不是道德评价；传统低不直接推断不守规则。
- [ ] 事实、计算、工作情景推断清楚区分；不编造业务数据/损失/绩效。

## PPT与交付
- [ ] 用所选具体模板；个人每人一页，群体不是个人页合集。
- [ ] 占位已替换，没有旧人名、旧分数、旧备注/元数据/图表缓存。
- [ ] 文字可编辑；图像形式明确，图表比例未拉伸。
- [ ] 完整证据只在获授权版本；身份对照仅明确请求且受众有权查看时提供，不附无关联系方式。
- [ ] 所有页面实际渲染目检；转换失败时如实说明，不伪造预览。
- [ ] 文件确实存在、能打开；确认后实际交付，不只说“开始处理”。

## GitHub版本
- [ ] 测试、有限发布检查通过，并做人工内容/二进制/暂存列表核查。
- [ ] 没有把已跟踪真实数据当作被.gitignore保护；历史泄露另行处理。
- [ ] 用户未明确要求发布时，没有自动创建仓库、提交或推送。


## v2.1 分支要求验收
- [ ] 采用管理汇报陈述，不只变口语、不用随意贬损词，也不把专业词全部禁用。
- [ ] 优势解释工作价值，风险解释工作影响；建议与具体行为对应。
- [ ] HPI同页有群体共性与实际差异卡，有依据时高低两端都考虑；选择理由可追溯，不叫统计显著。
- [ ] 单批均值/中位值直接标在点位；跨批的颜色按人群而非统计量编码。
- [ ] 所选群体结构及总结三栏与用户要求一致，不锁死历史页码。
- [ ] 姓名模式、受众授权和映射已确认；真实名单不在公开模板或仓库中。
- [ ] HDS源区间与显示标签分开记录，映射在图例/脚注说明，不因换颜色改阈值。
- [ ] 右侧观察对象依据当前分布选择，不固定5人、不给人才优劣排序。
- [ ] 解读卡、措辞检查和人工审稿都完成；不以关键词检查代替语义判断。
